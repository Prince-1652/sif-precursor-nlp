# Technology Stack

The SIF Precursor system is built using an aggressive, modern tech stack designed for speed, type safety, and maintainability.

## Frontend Stack

### Core Framework: Next.js (App Router) & React 19
- **Why chosen:** Next.js provides out-of-the-box routing, server-side rendering (SSR), and seamless API route integration. It was chosen over plain React or Vue.js because it allows for static generation of dashboard shells and dynamic fetching of metric data, resulting in a significantly faster perceived load time.

### Styling: Tailwind CSS
- **Why chosen:** Utility-first CSS allows for rapid prototyping and styling directly within component files. It eliminates the need for context-switching between TSX and CSS files, ensuring perfectly consistent design tokens (colors, spacing) across the app without bloated CSS bundles.

### Data Visualization: Recharts
- **Why chosen:** A composable, React-native charting library. It was chosen over Chart.js or D3 because it utilizes a declarative component approach (`<LineChart>`, `<Tooltip>`) that blends perfectly with Next.js architecture and handles responsiveness natively.

### Icons: Lucide React
- **Why chosen:** Lightweight, beautiful, and consistent SVG icons that don't heavily impact the bundle size.

## Backend Stack

### Core Framework: FastAPI & Python 3.10+
- **Why chosen:** FastAPI is exceptionally fast and natively asynchronous. It was chosen over Django or Flask because of its automatic Swagger UI generation, strict type-checking via Pydantic, and ability to handle heavy concurrent I/O bounds (like waiting on multiple LLM API calls in parallel) without blocking.

### Validation & Serialization: Pydantic
- **Why chosen:** Enforces strict typing for all incoming requests and outgoing responses. If a frontend sends an invalid payload, Pydantic catches it immediately, returning a structured 422 error before the logic ever touches the database.

### Database ORM: SQLAlchemy & Alembic
- **Why chosen:** SQLAlchemy is the standard for robust, Pythonic database interactions. Alembic provides migration management. This combination was chosen so that the database structure is defined in code (`app/models/`), allowing developers to interact with Python objects instead of raw SQL strings.

### Testing: Pytest & Pytest-Asyncio
- **Why chosen:** Essential for stress-testing complex NLP extraction boundaries and verifying dynamic metadata weights using TDD (Test-Driven Development) methodologies. Pytest's fixture system makes mocking LLM dependencies effortless.

## Artificial Intelligence & NLP

### Primary LLM Provider: Google Gemini API
- **Why chosen:** Gemini provides excellent reasoning capabilities and vast context windows, making it highly effective for text normalization, translating complex site-specific slang, and extracting contextual entities from safety reports.

### Fallback LLM Provider: Groq
- **Why chosen:** Included as a secondary provider. Used to ensure system resilience.

### Language Detection: FastText
- **Why chosen:** An ultra-fast, lightweight NLP model created by Facebook. It runs locally and deterministically, taking microseconds to detect a language. This was chosen over asking an LLM "what language is this?" which would waste precious API time.

---

## Database

### Engine: PostgreSQL
- **Why chosen:** PostgreSQL is a highly advanced, enterprise-grade relational database. It was chosen to prove true scalability. Unlike local file-based databases, Postgres seamlessly handles the massive concurrent write-loads generated by FastAPI's background workers during bulk CSV ingestion without locking. Furthermore, it sets the foundation for future advanced features like semantic search using the `pgvector` extension.
